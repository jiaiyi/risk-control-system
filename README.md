# 电商风控系统（AI_Risk）

面向电商业务的实时风险控制系统 —— 规则驱动 · 决策可解释 · 流程可闭环 · 审计可追溯。

在**登录、营销领券、下单、支付、售后申请、物流投诉**六个关键节点实时完成「特征计算 → 规则匹配 → 评分决策」全链路，覆盖刷单、薅羊毛、恶意退款、黄牛囤货、撞库盗号等风险场景。

## 快速开始

### 1. 环境要求

- Python 3.12
- MySQL 8.0+（库名 `ecs`）
- Redis（可选，关闭后自动降级直查数据库）

**本机已安装**（位于 `D:\idetools_main\`）：

| 服务 | 版本 | 端口 | 启动方式 |
|------|------|------|---------|
| MySQL | 8.0.40 | 3306 | 双击 `D:\idetools_main\mysql\start-mysql.bat` |
| Redis | 5.0.14.1 | 6379 | 双击 `D:\idetools_main\redis\start-redis.bat` |

一键启动两个服务：`D:\idetools_main\start-db-services.bat`

> 说明：Redis 使用 Windows 移植版（tporadowski），版本为 5.0 —— Redis 官方自 6.0 起不再提供 Windows 版本。
> 本项目用到的命令（SETEX / GET / DEL / ZSET / TTL）5.0 均支持。
>
> MySQL 连接账号：`root` / 空密码（仅本地开发环境）。

### 2. 安装依赖

> **⚠️ 本机 pip 不可用** —— 新建 venv 里的 pip 取不到索引（`from versions: none`，且无任何连接日志），
> 即使清空代理变量、换镜像源均无效（已实测）。**统一改用 uv**。

```bash
python -m venv .venv
export VIRTUAL_ENV="$(pwd)/.venv"                    # Windows Git Bash
uv pip install -r requirements.txt --python .venv/Scripts/python.exe
```

uv 的清华源与缓存已在用户级 `%APPDATA%\uv\uv.toml` 配置好（`cache-dir=D:\uv-cache`），无需额外参数。

### 3. 配置环境变量

```bash
cp .env.example .env
# 编辑 .env，至少填写 DB_PASSWORD 与 LLM_API_KEY
```

### 4. 初始化数据（待 T-02~T-05 完成后可用）

```bash
python scripts/init_db.py      # 建库 + 41 条规则 + 19 张业务只读表数据
python scripts/seed_demo.py    # 预填最近 7 天的风控演示数据（可选，但强烈建议）
```

`init_db.py` 只灌**业务侧**数据，风控运行表（事件 / 评估 / 案件 / 画像 / 名单）是空的，
所以刚初始化完仪表盘全是 0、「近 7 天趋势」是一条空轴。

`seed_demo.py` 用真实链路（特征 → 规则 → 决策 → 落库）造一批最近 7 天的数据：
通过 / 标记 / 人工审核 / 拒绝四档齐全，带案件、名单条目与审计流水，
并把时间戳回填到 7 天里 —— 仪表盘、案件管理、名单管理、审计日志、资损防护立刻有内容。

### 5. 启动服务

```bash
python -m app.main
# 或：uvicorn app.main:app --reload --port 8000
```

访问：
- 登录页 `http://localhost:8000/login`
- 健康检查 `http://localhost:8000/health`
- 接口文档 `http://localhost:8000/docs`

### 6. 登录与角色权限

> ⚠ 这一节是**超出 `specs/PRD.md` 本期范围**的新增项。PRD.md:110 原本写明
> 「本期不实现登录鉴权（RBAC）」；因用户明确要求，补上了最小登录页 + 服务端
> 角色拦截。权限矩阵严格照抄 PRD.md:91-108，未新增任何 PRD 之外的角色。

5 个演示账号，口令统一为 `risk@2026`（登录页可点击一键填充）：

| 账号 | 姓名 | 角色 | 能做什么 |
|------|------|------|----------|
| `zhangcx` | 张晨曦 | 风控策略师 | 规则管理、名单管理与导入、仿真、风险检查、AI 助手、审计日志 |
| `shenhey` | 沈核言 | 风控审核员 | 案件审核处置、仿真、风险检查、AI 助手；**名单只读** |
| `fengxs` | 冯析数 | 数据分析师 | 仿真、案件与名单只读、用户画像、关联图谱 |
| `yunwq` | 云维清 | 系统管理员 | 系统配置与阈值、健康度监控、审计日志 |
| `shenjr` | 慎计仁 | 审计人员 | 规则/案件/名单/画像/图谱/配置**只读** + 审计日志 |

实现要点：

- **服务端拦截**：`app/main.py` 的 `auth_middleware` 按 `PAGE_PERMISSIONS` /
  `API_PERMISSIONS` 判定。白名单式放行 —— 新增页面忘了登记权限时默认「要登录」，
  而不是「人人可进」。页面未登录 302 到 `/login?next=`，接口未登录 401，
  权限不足页面/接口分别给 403（**401 与 403 必须分开**，否则前端无法判断
  该跳登录页还是提示无权限）。
- **会话存 Redis**（`risk:auth:sess:<token>`，TTL 8 小时，访问时滑动续期），
  Cookie `rc_session` 带 `HttpOnly` + `SameSite=Lax`。口令用 PBKDF2-SHA256 加盐哈希，
  比对走 `hmac.compare_digest`；账号不存在时也做一次哈希，避免用响应时间探测账号是否存在。
- **fail-closed**：`app/auth.py` 刻意**不用** `app/cache.py` 的 `safe_*` 封装 ——
  那套把 Redis 异常吞成「未命中」，对旁路缓存是对的，对鉴权是危险的：Redis 故障
  会被伪装成「会话不存在」，更糟的实现会顺手放行。鉴权后端不可用时直接 503。
- **审计落真实操作人**：PRD 预留的 `risk_audit_log.operator` 现在写入
  `姓名(账号)`（如 `张晨曦(zhangcx)`），不再是无差别的 `admin`。

**已知简化**（演示环境够用，生产需补）：不做注册/改密/找回；不做 CSRF token
（同源 + `SameSite=Lax` 已覆盖）；不做「审核员仅拒绝时方可新增黑名单」的行内细粒度
限制（当前审核员对名单为只读，反而更严格）；单进程内存态无并发会话上限。

### 7. 自检（可选）

「只读」格子的读通写拒、侧边栏按权限渲染、开放重定向防护）：

```bash

```

让界面直接回到有演示数据的状态。加 `--no-restore` 则保留脚本跑出来的数据供排查。

## 关键设计约束（实现时不可违背）

来自 `specs/SPEC.md` 第 11.1 节的已确认决策：

1. **评分链路顺序固定**：`max(分值) → +BONUS×额外条数 → +灰名单加严 → 一票否决判定 → 截断 100`
2. **一票否决仅由 `rule.risk_level == '极高'` 触发**，不受灰名单加严影响
3. **订单维度与商品维度特征禁止缓存**（含本次订单实时金额）
4. **缓存只加速读，不改变判定结果**；缓存不可用时自动降级直查数据库，**不阻断风控主链路**
5. **名单判定路径不产生特征快照**（0 条 `risk_feature`）
6. **单次风控检查的全部落库操作在同一事务内提交**，任一步失败整体回滚
7. **处置回写只允许改写「未终结」状态的单据**（已发货订单、已完成售后不回写）
8. **规则删除为逻辑删除**；**审计表只追加，不提供更新/删除接口**
9. **规则条件求值使用白名单运算符**，禁止 `eval` / `exec` / 第三方沙箱库
10. **仿真回放零副作用**（不写事件、不写特征、不建案件、不动画像）
